# BewlyCat 通用设置复用设计

## 目标与决策

- 目标：将 BewlyCat 设置中全部非 Bilibili 专属能力映射到 betterLD，并形成可分阶段实施的完整设计。
- 根因 / 影响：前一轮审计给出可复用项，但尚未形成统一的数据模型、路由边界、存储协议和验收标准；直接实现会产生设置重复、作者数据回退、后台标签页权限和同步数据丢失风险。
- 决策：保持无依赖 MV3；`betterld.config.js` 继续作为默认值和 limits 的唯一配置源；新增能力经共享规范化入口；保留当前壁纸、主题、卡片和路由行为；Bilibili 播放器、动态、评论、账号和专属搜索能力排除。
- 设计交付文件：`design.md`。

## 计划

1. 检索项目知识、journal、现有设置 / 内容脚本，并核对 BewlyCat 设置来源。
2. 设计设置页分组、完整设置模型、路由范围、运行时数据流、安全边界和分阶段实施方案。
3. 进行独立设计审查，修订作者 / 摘要解耦、受限 CSSOM、自定义后台打开消息链、同步投影、模型字段和原始审计项追踪。
4. 执行文档级静态检查并记录结论。

## 验证记录

- 已读取当前 `betterld.config.js`、`src/options.html`、`src/options.js`、`src/content.js`、`src/content.css` 和项目 journal 相关记录。
- 已核对 BewlyCat 外观、卡片、链接、搜索、顶部栏 / 侧栏、快捷键、维护设置及其存储语义。
- 独立审查发现 6 项设计缺口：作者与摘要请求耦合、custom CSS 校验过弱、后台打开缺少 service worker 链、同步缺少投影和冲突协议、模型缺少字段、缺少原始 1/2/3 追踪表；均已修订到 `design.md`。
- 文档级 Node 检查通过：设置模型可解析，共 96 个顶层字段；重复顶层键为 0；原始审计追踪章节齐全。
- `git diff --check -- .pi/tasks/2026-09-12-bewlycat-reuse-design/design.md` 通过；设计文件存在；主章节计数为 15。
