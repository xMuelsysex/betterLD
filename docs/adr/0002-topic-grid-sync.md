# 2. 卡片网格镜像站点顺序，刷新时复用卡片节点

- **Status**: Accepted
- **Context**: 原站主题列表每次变动（底部「查看 N 个新的或更新的话题」被点开、站点轮询合并新主题、相对活动时间文本刷新）都会让卡片网格整张重建：实测点一次提示条后 32/32 张卡片被销毁重建，网格节点本身也被替换，用户正在阅读的位置与已加载的正文预览随之丢失。曾改为「只增不改、新主题追加到网格末尾」，但那样用户点提示条后新主题落在网格末尾、当前视口看不到任何变化（表现为「刷新不出来」），与原站体验不一致。
- **Decision**: 网格顺序镜像原站列表顺序。同步时复用已有卡片节点：未知主题新建卡片，已存在主题沿用原节点，再按原站顺序把卡片就位（`insertBefore` 移动，不重建）；站点「查看 N 个新的或更新的话题」提示条由用户点击，操作栏刷新按钮与 `refreshTopics` 快捷键触发同一次合并，都不再整页重载。
- **Consequences**: 更容易：刷新后新主题与更新过的话题出现在列表顶部，与原站一致；卡片节点、正文预览与已加载摘要在整个页面生命周期内保持；滚动位置由浏览器锚定保持；刷新不再走整页重载，也不会因重载撞上站点的质询页。更难：顺序跟随原站意味着卡片会移动，不再是「只增不改」；被原站移除的主题其卡片会保留到网格重建；卡片上的回复数与活动时间在页面生命周期内不再更新。
- **History**: 09-19 首版为「只增不改、新主题追加到末尾、插件自动点击提示条」；同日修订为「提示条由用户点击」；同日再修订为当前的「镜像原站顺序 + 节点复用 + 刷新入口不重载页面」，原因是末尾追加让刷新对用户完全不可见。
